= 了解 ONTAP 外部 LUN 导入
:allow-uri-read: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
外部 LUN 导入 (FLI) 是一种 ONTAP 功能，它通过将用户数据从外部阵列 LUN 复制到 ONTAP LUN 来实现块级别 (LUN) 数据迁移。ONTAP 通过充当 SCSI 启动程序从外部 LUN 读取数据并写入目标 ONTAP LUN 来执行迁移。

FLI 严格在 LUN 级别运行，用于 SAN 迁移；它不是文件级迁移工具（NAS/文件协议迁移（如 NFS/SMB）需要不同的方法）。FLI 支持离线和在线迁移。在离线模式下，主机 I/O 在导入期间停止；在在线模式下，主机操作在短暂切换后恢复，同时在后台继续导入。

外来 LUN 出现在 ONTAP 存储堆栈中，必须明确标记为外来，以防止意外覆盖/所有权。FC FLI 使用 FC 后端连接（启动器端口、分区/屏蔽），而 iSCSI FLI，后端使用绑定到群集间连接的 iSCSI 软件启动器，而迁移后的面向主机的（前端）协议仍然可以是 FC 或 iSCSI，具体取决于设计。

.离线和在线 FLI 对比
以下总结了离线和在线迁移方法之间的主要区别。

[cols="3"]
|===
| 区域 | 离线 FLI | 联机 FLI 


| 导入期间的主机 I/O | 主机 I/O 在完整导入期间停止。 | 在导入副本继续进行时（切换后），主机 I/O 可以运行。 


| 停机时间配置文件 | 需要在整个导入窗口内停机。 | 设计为基本无中断，通常只需要短暂停机即可切换。 


| 运营用例 | 当应用程序或主机模型可以接受或需要更长的停机时间时，效果最佳。 | 最适合必须最大限度地减少停机时间并且可以容忍后台复制活动的情况。 
|===

[[learn-about-key-features-and-benefits-of-ontap-foreign-lun-import]]
== 了解 ONTAP Foreign LUN Import 的主要功能和优势

ONTAP 外部 LUN 导入 (FLI) 是一种内置的数据块迁移功能，可将数据从外部（第三方）阵列 LUN 复制到本机 ONTAP LUN，并支持离线和联机迁移样式。FLI 旨在将 SAN LUN 从一系列第三方阵列迁移到 ONTAP，它提供了一致的迁移方法，有助于跨不同主机和阵列标准化规划、执行和验证。



[[key-features]]
=== 主要特点

* 在线和离线迁移以满足业务停机时间要求。
* 独立于操作系统的块级迁移不依赖于主机卷管理器或操作系统实用程序来移动数据。
* 适用于异构 SAN 环境，旨在将 SAN LUN 从一系列第三方阵列迁移到 ONTAP。
* 后端传输非常灵活，支持 FC 和 iSCSI 后端连接，但支持的配置取决于互操作性验证。
* 利用标准 SAN 路径模型的本机多路径和负载平衡支持。
* CLI 驱动的控制和可见性，实现可重复的执行和运营监控。




[[key-benefits]]
=== 主要优势

* ONTAP FLI 包含在 ONTAP 中。无需单独的迁移应用装置即可执行基于 FLI 的 LUN 导入。
* 通过启用在线工作流程降低停机风险，在短暂切换后，主机可以继续访问，同时在后台继续导入。
* 一致的迁移方法，有助于跨不同主机和阵列标准化规划、执行和验证。
* 支持复杂的过渡场景，包括 7 Mode 到 ONTAP 迁移，在过渡工作流程中可以解决对齐和格式考虑因素。
* 强力支持的运营模式，虽然专业服务不是强制性的，但 NetApp 推荐专业服务或合格的合作伙伴进行范围界定、规划和培训，以应对除简单迁移之外的任何事情。




[[learn-about-the-ontap-foreign-lun-import-prerequisites]]
== 了解 ONTAP 外部 LUN 导入先决条件

在启动 ONTAP Foreign LUN Import (FLI) 之前，必须具备几个先决条件，以确保成功迁移。这些先决条件涵盖了 FLI 流程正常运行所必需的兼容性、连接性和配置要求。

* 后端连接必须可用于所选传输：
+
** FC FLI 要求每个控制器至少有一个可以在启动程序模式下运行的 FC 端口（对于冗余，首选两个端口，每个结构一个）。
** iSCSI FLI 需要集群间 (IC) LIF（或能够托管 IC LIF 的以太网端口），因为 iSCSI 软件启动程序将出站会话绑定到 IC 连接。


* 在导入之前，必须能够在 ONTAP 中发现外部 LUN。外部阵列 LUN 必须在 ONTAP 存储堆栈中可见（发现是导入的先决条件）。
* 在 ONTAP 中将源 LUN 标记为"外部"。发现外部 LUN 后，必须明确标记为外部，以防止意外所有权或覆盖行为。
* 源 LUN 必须稳定。在导入工作流期间，外来 LUN 不得扩展或收缩。
* 外来 LUN 必须使用 512 字节扇区（512B 块大小）以实现导入兼容性，其他扇区大小不支持导入。
* 目标 ONTAP LUN 必须与源 LUN 大小匹配。"使用外部磁盘创建 LUN"工作流可确保目标 LUN 的创建大小正确。
* 必须根据前端协议计划将目标 ONTAP LUN 映射到至少一个 igroup，以便可以在工作流的正确阶段连接主机。
* 在开始导入副本之前，必须通过导入关系将外部 LUN 和目标 ONTAP LUN 配对。


在创建导入关系之前保持目标 ONTAP LUN 脱机；创建关系后，只有在执行联机 FLI 时才能使 LUN 联机，以便在继续复制时主机可以恢复 I/O。



[[learn-about-ontap-foreign-lun-import-supported-configurations-and-platforms]]
== 了解 ONTAP Foreign LUN Import 支持的配置和平台

ONTAP FLI 必须部署在受支持的配置中，以确保可预测的行为和完全可支持性。

* 所有 FLI 迁移都是在 LUN（块）级别执行的；文件和协议级别的迁移不在 ONTAP FLI 范围之内。
* 计划每个节点最多 8 个并发导入作为建议的起点。在最佳情况下，每个节点不超过 16 个并发迁移，如果观察到主机延迟或导入延迟增加，则减少并发数。
* 从 ONTAP 9.12.1 开始，用于导入的最大外来 LUN 大小为每个 LUN 125 TB。有关更多详细信息，请参见知识库文章 link:https://kb.netapp.com/on-prem/ontap/da/SAN/SAN-KBs/Unable_to_migrate_Array_lun_greater_than_16_TB_using_FLI["无法使用 FLI 迁移大于 16 TB 的阵列 LUN"^]。
* iSCSI 会话扩展限制（后端 iSCSI）：
+
** 每个 IC LIF 1 个启动程序
** 每个 LIF 最多 16 个会话
** 每个节点最多 32 个会话


* iSCSI 协议约束：
+
** 无 iSCSI 发现会话
** 无多连接会话 (MCS)
** 不支持错误恢复级别 > 0（仅限 ERL0）
** iSCSI 启动程序 LIF 使用不支持 IPv6


* 安全和管理可用性说明：
+
** 不包括 CHAP
** iSCSI FLI 操作的 REST API 覆盖不可用（仅限 CLI 工作流程）。


* 在线导入的运营规划说明：
+
** 在在线 FLI 中，主机 I/O 和导入副本共享后端资源
** 可以暂停和恢复导入以保护主机延迟
** 如果可能，应安排在非高峰时段进行迁移






[[supported-configurations-and-platform]]
=== 支持的配置和平台

由于新配置会随着时间的推移而合格，因此支持的组合可能会发生变化。对于每次迁移，根据当前的互操作性指南验证端到端堆栈（源阵列 + 主机 + 结构/网络 + ONTAP 目标）。

.支持的目标位置（您可以迁移到的位置）
* ONTAP 是 FLI 迁移的唯一支持目的地。FLI 旨在将数据导入 ONTAP LUN；不支持迁移到第三方目标存储。
* 对于 iSCSI FLI，iSCSI 软件启动程序与 FLI 堆栈集成，专门用于启用使用 iSCSI/TCP 后端连接的外部 LUN 发现和导入。


.支持的 ONTAP 平台覆盖范围（目标平台）
平台覆盖范围取决于用于发现/导入的后端传输：

* FC 后端 FLI（传统）支持 AFF / ASA / ASA r2 / FAS 上的 ONTAP（根据 iSCSI 测试设计中的比较表）。
* iSCSI 后端 FLI 扩展了覆盖范围，包括 AFF / ASA / ASA r2 / FAS / ONTAP Select / Cloud Volumes ONTAP (CVO) （根据相同的比较）。


.支持的源阵列和鉴定方法
* 使用 FC 后端 FLI，支持的外部阵列通常通过已建立的互操作性列表和资格认证指南进行验证（支持的列表会随着新阵列的合格而演变）。
* 使用 iSCSI 后端 FLI，默认情况下不会对外部阵列进行资格预审；在提交生产迁移之前，客户应使用提供的资格审批工具（例如 sanlunmigrate / offtap sanlunmigrate）执行现场资格审批。


.主机操作系统和光纤/交换机支持（端到端验证）
* 主机操作系统支持应与所选前端协议（FC 或 iSCSI）和迁移后主机配置的 SAN 主机互操作性指南保持一致。
* 交换机/结构支持还必须作为端到端配置的一部分进行验证（特别是对于需要分区/屏蔽的 FC 环境）。


.迁移后要求（切换后继续支持）
导入完成且主机正在 ONTAP LUN 上运行后，请确保支持最终稳态配置。这包括主机多路径、HBA/驱动程序/固件级别、分区/屏蔽 (FC)、iSCSI 配置（如果使用）以及您计划使用的任何 ONTAP 功能交互。

.iSCSI FLI 专用护栏（对可支持性很重要）
* iSCSI FLI 使用集群间 (IC) LIF 进行后端 iSCSI 会话。当现有 IC LIF 已在另一个子网上建立时，仅为了访问外部目标而在不同子网上创建新的 IC LIF 被视为不受支持的规划指导。
* iSCSI 启动程序会话配置仅用于迁移，应在迁移完成后清理，以避免操作副作用，包括升级和还原考虑因素。




[[best-practices]]
=== 最佳实践

NetApp 强烈建议您提供专业服务或合作伙伴专业服务，参与确定迁移范围并制定迁移计划，以及培训客户人员如何使用外部 LUN 导入（ Foreign LUN Import ， FLI ） 7- 模式向 ONTAP 执行数据迁移。

* 至少在迁移项目之前一周执行一次或多次测试迁移，以验证配置、连接和吞吐量；发现任何其他问题；并验证您的方法。
* 为了最大程度地提高吞吐量，每个节点同时运行的迁移不能超过 16 个。
* 不需要验证，但我们建议您验证导入和迁移的 LUN 的子集以验证导入过程。
* 使用测试迁移中观察到的吞吐量来计划生产迁移
